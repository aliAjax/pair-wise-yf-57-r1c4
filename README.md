# pair-wise-yf-57 野外巡护离线调查应用

## 源提示词摘要
巡护员离线记录观察、轨迹点、样本编号、风险等级和现场情况，回到有网络环境后同步给站点负责人。负责人复核重复观察、位置异常、证据缺失和能力范围外事项；多人修改同一记录时保留版本并允许合并，应用需要适配手机屏幕、电量、弱网和后台恢复。

## 技术栈
Taro 3 + React + TypeScript + NutUI + Redux Toolkit + RTK Query + React Hook Form + Zod + Taro 国际化方案。

## 已实现闭环
- 观察记录、轨迹点、样本三类业务对象，统一接入**可续作的合并账**。
- 新建现场记录、记录 GPS 轨迹点、提交样本、负责人复核与样本核验。
- **保存即入账**：每条记录带设备号与修订号（`rev`），稳定编号 `设备号+UUID` 重传不变。
- **幂等重传**：POST 按稳定编号去重，站点已有同版本直接确认（`duplicate`），只入账一次。
- **断点续作**：逐条 POST，每条确认后立即落游标（`lastAckedRev` + 字段快照）；弱网中断后从已完成部分继续，不重复入账。
- **逐字段合并**：联网后拉取站点快照按稳定编号逐字段合并——站里的复核意见（`reviewNote`）保留，本地新写的字段优先；站点新记录直接采用。
- **两版冲突**：观察或轨迹点两边都改过 → 保留本地版与站点版（标记 `冲突·两版`），不静默覆盖；可选择保留本地版 / 站点版，选定后保留版即为权威版本。
- **失效回退**：观察地点相对入账基线一变，复核结论立即撤销、样本核验退回待处理（`verified → submitted`），并标记待重新入账。
- 合并过程与结果（入账 / 去重 / 采用 / 合并字段 / 两版冲突 / 退回项）在页面汇总展示。
- Taro 本地存储持久化（含同步中间态）和移动端布局。

## 目录结构
```
src/
  sync/
    types.ts    三类记录与合并账的稳定类型定义
    device.ts   设备号与稳定编号
    ledger.ts   合并引擎：逐字段合并、两版冲突、地点变更失效回退
    server.ts   站点模拟服务：幂等 POST、弱网中断注入、站点快照
  store/index.ts  台账 slice + runSync 续作 thunk（POST 游标 → 合并 → 补 POST）
  pages/index/    现场记录 / 同步续作 / 冲突两版 / 失效提示
```

## 启动
```bash
npm install
npm run dev
```
开发端口：62022

> 注：在 linux-arm64 环境构建需额外安装 `@tarojs/binding-linux-arm64-gnu`（Taro 3.6.40 的可选绑定未覆盖该平台，4.x 绑定 NAPI 兼容可直接使用）。

## 合并账行为验证
```bash
node smoke.cjs
```
冒烟脚本用 babel 即时编译 TS，覆盖：两版冲突、逐字段合并、站点复核意见保留、样本改挂、地点变更失效回退、幂等入账、弱网中断与断点续作、冲突裁决。
