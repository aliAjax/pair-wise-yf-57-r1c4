# pair-wise-yf-57 野外巡护离线调查应用

## 场景
巡护员断网在野外记下观察、轨迹点和样本；回站后把本地记录与站账按**稳定编号**逐字段合并：
合并重复路段、样本改挂到幸存观察；两边都改过的观察/轨迹点保留两版，不静默覆盖；
站点复核意见始终保留，本地新写优先；同步可中断、可续传，重传只入账一次。

## 可续作的合并账（src/sync）
所有记录（observation / track / sample）装在统一信封 `RecordEnvelope` 里：

- **保存即带设备与修订号**：`id`（设备内断网生成的稳定编号）、`deviceId`、单调 `rev`，
  每个业务字段有独立的 `fieldRevs`；每次保存产生一条 `OutboxOp`，幂等键为 `设备:稳定编号:修订号`。
- **三向逐字段合并**（`merge.ts` / `StationLedger.applyOp`）：以设备上次对齐站点的快照为 base，
  设备只改了某字段而站点没动 → 自动合并；站点没动而设备没改 → 取站点；两边都改同一字段 → 冲突。
- **站点字段受保护**：复核（reviewState/reviewComment）、核验（verifyState/verifyComment）是站点专属字段，
  设备信封永远不能覆盖；站点意见在任何合并路径下都保留。
- **两边都改不静默覆盖**：观察、轨迹点产生两个活跃版本——规范记录放本地版、`station-fork` 整版留存站点原值；
  样本不分叉，按**本地新写优先**入账，站点原值在冲突条目里留档；冲突解决后归档落选版本。
- **观察地点一变立即失效**：本地保存时即触发；同步到站点再权威触发一次。观察复核结论与所有挂在它上面的
  样本核验结论立即退回「待处理」，复核/核验**意见原文保留**，并记录失效原因。
- **重复路段/重复观察归并**：轨迹点按距离（50 m）+时间窗（5 分钟）判重，观察按距离（80 m）判重；
  被并记录 `active=false / mergedInto=幸存id`，挂在它上面的样本改挂到幸存观察；若两观察地点不同，
  改挂样本的核验同样退回待处理。同批次先到的观察被归并、后到的样本会沿 `mergedInto` 链跟随改挂。
- **断点续传与幂等**：站点按幂等键去重（同修订重传只入账一次）；设备维护 `ackedSeq` 水位，
  传一半失败时已完成部分留在站账、未完成部分留在 outbox，重试自动接在已完成部分之后；
  「应答丢失」导致的整段重发会被识别为重复并继续推进水位。
- **可审计**：设备账与站账各有只追加流水（保存/字段合并/去重/分叉/失效/归并/失败）。

## 目录
- `src/sync/types.ts` 信封、冲突条目、出站操作、流水与同步结果类型
- `src/sync/merge.ts` 纯函数：三向字段合并、距离判重、地点失效、样本改挂
- `src/sync/ledger.ts` `DeviceLedger`（离线保存/续传/增量对齐）、`StationLedger`（入账/复核/核验/归并/分叉）
- `src/store/index.ts` Redux 接线 + Taro 存储持久化（设备账、站账分别落盘）
- `src/pages/index/index.tsx` 现场录入、模拟断网/续传、站端纠错、站点复核核验、冲突两版抉择、流水查看
- `tests/ledger.test.ts` 17 个引擎验收测试（`npm test`）

## 页面可演示的完整链路
1. 断网「现场记录」：观察（带坐标/风险）+ 样本（自动挂到该观察）；「记录当前轨迹点」。
2. 「模拟传到一半断网」后再点同步：可看到新入账/重传去重计数与断点 seq，重试接其后完成。
3. 站点操作区：复核通过/驳回（带意见）、核验通过/驳回、站端纠错备注（制造同字段两边都改）。
4. 设备侧「本地补备注 / 本地挪位置 / 本地改数量」：分别演示自动合并、地点失效、样本本地优先。
5. 冲突卡片：观察/轨迹显示本地版+站点留版两个徽章，可择一采用；样本提示本地优先、站点值留档。
6. 重复路段：多台设备在 50 m/5 分钟内的轨迹点同步后自动归并，样本改挂在观察列表可见。

## 技术栈
Taro 3 + React + TypeScript + NutUI + Redux Toolkit + RTK Query + React Hook Form + Zod。

## 启动
```bash
npm install
npm test         # 合并账引擎测试（17 项）
npm run typecheck
npm run dev      # H5 开发，端口 62022
```

> 注：Taro 3.6.40 的官方原生绑定未发布 linux-arm64 预编译包，在 arm64 Linux 上 CLI 构建会因
> `@tarojs/binding` 缺二进制而无法启动（x64 macOS/Linux/Windows 正常）；本仓库的 TS 类型检查与
> 引擎测试不依赖该绑定。
